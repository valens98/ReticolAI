# Reticolo

Reticolo looks at a picture and tells you two things: whether it's a real photograph or something generated by AI, and if it's real, whether it looks untouched, re-uploaded/re-compressed somewhere along the way, or re-digitized (rescanned, or re-photographed off a screen or print). Everything happens in your browser — no image you drop in ever gets uploaded anywhere.

**[Try it →] https://valens98.github.io/ReticolAI/** 

## Where this came from

This started as Project for the Computer Vision course at Sapienza University of Rome, taught by Prof. Irene Amerini (ALCOR Lab), done together with Lorenzo Sambucci and Davide Sparvoli. The assignment was to build a multi-task model that jointly detects AI-generated images and classifies the kind of post-processing a real photo has gone through, using the RRDataset released alongside Li et al.'s ICCV 2025 paper.

Once the project was graded and done, I wanted to keep it around as something I could actually use — drop in a photo and get an answer, instead of opening a notebook every time. That meant retraining the model with a few changes aimed specifically at making it hold up outside a curated academic dataset, and exporting it to run entirely client-side so it could live on a plain GitHub Pages site with no backend behind it.

## The shortcut problem

One thing that came up during the original project is worth explaining, because it's the reason this version was retrained rather than just exported as-is.

In the dataset, every AI-generated image happens to be a 512×512 PNG, while real photos come in whatever size and format they were originally saved in. A model can quietly learn to key off *that* — "this file is a uniform PNG, must be AI" — instead of learning the actual visual traces that generative models leave behind. It's a real accuracy boost on the exam's test split, because the split has the same quirk, but it's a trap: a real photo saved as a PNG would get flagged as AI, and an AI image downloaded as a JPEG would slide right through.

The deployment version fixes this by randomly rescaling and randomly re-compressing images as JPEG during training, so the format itself stops being a useful signal and the model has to rely on something closer to the real thing.

## How it works

- **Backbone:** MaxViT-T, fully fine-tuned rather than frozen.
- **Two heads sharing one backbone:** one for real vs. AI-generated, one for the post-processing category.
- **Multi-scale features:** instead of only reading out the backbone's last stage, it concatenates three intermediate stages — tested against the alternatives during the original project and the best-performing option.
- **224×224 crops at native resolution.** Large images are split into up to a 3×3 grid of crops rather than resized down, because resizing would wash out exactly the high-frequency detail the model is looking at. The final answer is the average across all crops, and the page shows you the per-crop breakdown too.
- **Runs in the browser** via ONNX Runtime Web, using WebGPU when it's available and falling back to WASM otherwise. The model is exported in fp16, around 60MB, downloaded once and cached after that.

## How good is it, really

On a small slice of data held out of training entirely (240 images) it gets the real-vs-AI call right about 93% of the time, and re-compressing those same images as JPEG before evaluating only knocks that down to about 92.5% — which is the augmentation doing its job. The post-processing head does even better on this same slice, though the holdout is small enough that I wouldn't read too much into the exact number.

What matters more than any specific percentage is the scope: this was trained on one dataset, with a specific, published set of AI generators and post-processing methods behind it. It will very likely do worse, or just be wrong, on generators or manipulation pipelines it never saw during training. Treat it as a signal, not a verdict, and not as anything close to forensic or legal-grade evidence.

## Running it yourself

```bash
git clone <this repo>
cd <this repo>
python -m http.server 8000
```

Then open `http://localhost:8000`. Opening `index.html` directly by double-clicking it won't work — browsers block a local page from fetching the model file over `file://`.
